## Implementation choices within the approved design

Caches use immutable fingerprint directories and one COMPLETE record linked to metadata. Feature values are written in image batches and checksums are streamed. Formal image/mask hashes are checked against frozen manifests. The extractor constructs ResNet18 without download, loads the verified state dictionary strictly, freezes it, and keeps eval mode. Legacy setup/naming configuration status fields describe their original acceptance snapshots; current integration status belongs to this workflow's acceptance record.

The new execution configuration contains execution settings only. Scientific choices come from the frozen matrix. `plan` is read-only and imports no GPU runtime. Synthetic contexts must be strictly inside run/validation_tc2_gpu; formal contexts use only canonical mapped paths. No real-data action is invoked during step-5 implementation or acceptance.

The local tc2_setup.json includes a later acceptance summary while the remote compatibility file retains its original bytes. Neither is replaced. On TC2 the workflow reads the actual accepted setup job's setup_status.json, weights_info.json, and environment export hashes. Only isolated local core fixtures may use the recorded local summary when no actual job pointer is present. Unknown or failed new acceptance records never fall back to that summary. The remote compatibility configuration is checked read-only and is excluded from the upload payload.
